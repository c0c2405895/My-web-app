# AI Wardrobe

天気とワードローブの登録情報をもとに、今日のコーディネートを提案する Flask アプリです。
服の画像を登録し、提案への評価を蓄積することで、好みの色を次回の提案に反映します。

## ポートフォリオ概要

- **課題**: 毎朝の服選びに時間がかかり、所有している服も活用しきれない
- **解決策**: 現在地の天気・気温と手持ちの服を組み合わせ、理由付きでコーディネートを提案
- **工夫点**:
  - Open-Meteo API が利用できない場合も、フォールバック値でデモを継続
  - 画像のファイル名と入力内容から、カテゴリ・素材・暖かさをローカルで推定
  - 「好き／好みではない」の評価を次回の色選択に反映
  - モバイル表示、画像アップロード、プロフィール設定、通知設定に対応

## 技術構成

- Python / Flask
- HTML / CSS / JavaScript
- Open-Meteo Geocoding API・Forecast API
- JSON ファイルによるローカル永続化

## ローカルで実行

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:SECRET_KEY = "local-development-secret"
python app.py
```

ブラウザで <http://127.0.0.1:5000> を開いてください。

ログイン画面はポートフォリオ用のデモ認証です。任意の識別子とパスワードを入力すると利用できます。
本番運用では、ユーザー情報をデータベースに保存し、パスワードハッシュ・メール認証・CSRF対策を追加します。

## データと画像

実行時データは `app/wardrobe.json` と `uploads/` に保存されます。これらは `.gitignore` 対象です。
初回起動時にはサンプルデータが生成されます。

## 環境変数

| 変数 | 用途 | 既定値 |
| --- | --- | --- |
| `SECRET_KEY` | Flask セッション署名キー | 起動ごとにランダム生成 |
| `PORT` | 待ち受けポート | `5000` |
| `FLASK_DEBUG` | 開発デバッグモード（`1` のとき有効） | 無効 |
| `COOKIE_SECURE` | HTTPS 接続時の Secure Cookie（`1` のとき有効） | 無効 |

## 今後の改善案

現在のアプリには、今後さらに改善できる点があります。

### 1. 機械学習を使った推薦への発展

現在の提案機能は、気温・天気・服の暖かさ・ユーザー評価を条件分岐で組み合わせる
ルールベースの仕組みです。そのため、ユーザーの好みを複雑に分析したり、未知の
組み合わせを自動的に発見したりすることはできません。

今後は、評価履歴やコーディネート履歴を蓄積し、好きな色・カテゴリ・素材・季節ごとの
傾向を分析できる推薦機能へ発展させたいと考えています。

### 2. コーディネートの組み合わせが限定的

現在は主にカテゴリごとにアイテムを選択しているため、服同士の色・柄・シルエットの
相性までは十分に考慮できていません。また、同じ組み合わせが選ばれる可能性もあります。

色の組み合わせや季節感、過去に評価されたコーディネートをスコア化し、全体のバランスを
考慮して提案できるようにしたいです。

### 3. 初回登録の手間が大きい

現在は服を一着ずつ写真と名前を登録する必要があるため、初回利用時にワードローブを
作成するまでの負担があります。

複数画像の一括登録、画像ファイル名からの入力補完、カテゴリや色の一括設定などを実装し、
使い始めるまでの時間を短縮したいです。

### 4. 服の属性推定が簡易的

現在のカテゴリ・素材・暖かさの推定は、服の名前や画像ファイル名に含まれるキーワードを
利用しています。そのため、名前の付け方によっては正しく判定できない場合があります。

登録時にユーザーがカテゴリや色を選択できるようにし、将来的には画像認識 API を利用して
服の種類・色・柄・季節感を自動判定できるようにしたいです。

### 5. 一度着た服の表示を切り替える機能

現在は、前日に選ばれた服を次の日の提案から除外するかどうかを設定できません。
毎日違う服を着たい場合と、お気に入りの服を続けて着たい場合の両方に対応できるよう、
「前回着用した服を次回の候補から外す」オン・オフ設定を追加したいです。

この設定をユーザーごとに保存し、オンの場合だけコーディネート履歴を参照して候補を
調整する設計を検討しています。

### 6. データ保存と認証の強化

現在はローカルの JSON ファイルに服・評価・設定を保存しています。複数ユーザーでの利用や
複数端末からのアクセスには、SQLite または PostgreSQL への移行が必要です。
また、本番運用ではパスワードのハッシュ化、メール認証、CSRF対策も追加する必要があります。

### 7. コーディネート履歴と通知の拡張

提案されたコーディネートや実際に着用した服を履歴として保存し、カレンダー形式で確認できる
ようにしたいです。履歴をもとに、最近着ていない服や季節に合う服を提案する機能にも発展できます。

通知については、現在のブラウザー通知に加えて、サーバー側から定刻に通知を送る仕組みを検討します。
